# Students Database CRUD Application

**EWB Edu Tech Pvt. Ltd. — Python Backend Development Internship Project**

A beginner-friendly REST API for managing student records using **Python, FastAPI, and SQLite**. It implements the mandatory CRUD operations from the assignment. The optional Ollama AI extension is intentionally not included because the assignment states that it is not mandatory.

## Features

- Create student records with `POST /students`.
- List and filter records with `GET /students`.
- Retrieve a single student with `GET /students/{student_id}`.
- Partially update a record with `PATCH /students/{student_id}`.
- Delete a record with `DELETE /students/{student_id}`.
- SQLite database persistence between app restarts.
- Input validation for names, email, phone number, dates, and required contact information.
- Useful HTTP errors: `404` for a missing student, `409` for a duplicate email, and `422` for invalid input.
- Interactive API documentation and example requests.
- Responsive StudentHub web dashboard with student profile, add/edit/delete, live search, and course filter.
- CSV import, filtered CSV export, and downloadable CSV template. Import validates required names, ISO dates, and contact information; duplicate emails are reported.
- Sort by ID, name, course, date of birth, or enrollment date; switch ascending/descending order.
- Client-side pagination with 5/10/25/50 rows per page.
- Course-distribution chart and record-completeness insights.
- Persistent dark/light theme switch, success/error messages, and date/contact validation.
- Automated tests for CRUD, validation, and filtering.

## Requirements

- Python 3.10 or newer recommended.
- Internet access for the initial dependency installation.

## Setup on Windows

Open Command Prompt or the VS Code terminal in this project folder.

```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Run these commands from the folder that directly contains `requirements.txt` and the `app` folder. If a previous attempt left a broken `.venv`, close the terminal, remove that `.venv` folder, open a new Command Prompt in the project root, and recreate it. If activation is not needed, install with `.venv\Scripts\python.exe -m pip install -r requirements.txt`.

## Run the API

From the project root folder, run:

```bat
python -m uvicorn app.main:app --reload
```

Then open these URLs in your browser:

- API home: http://127.0.0.1:8000/
- **Interactive Swagger UI:** http://127.0.0.1:8000/docs
- Alternative API docs: http://127.0.0.1:8000/redoc
- Health check: http://127.0.0.1:8000/health

The SQLite database file `students.db` is created automatically in the project folder when the application starts. Keep this local database out of GitHub; the `.gitignore` file already excludes it.

## How to test in Swagger UI

1. Start the server with `python -m uvicorn app.main:app --reload`.
2. Open http://127.0.0.1:8000/docs.
3. Expand `POST /students`, choose **Try it out**, and submit the example JSON below.
4. Copy the returned `id` and use it in the GET, PATCH, and DELETE endpoint paths.
5. Stop and start the API again, then call `GET /students` to confirm that records persist in SQLite.

### Example JSON for `POST /students`

```json
{
  "name": "Aarav Sharma",
  "date_of_birth": "2005-04-18",
  "email": "aarav.demo@example.com",
  "phone": "+91 9876543210",
  "course": "B.Tech CSE",
  "address": "New Delhi, India",
  "enrollment_date": "2026-08-01"
}
```

Use dummy information only. At least one of `email` or `phone` must be provided. The `id` is generated by the database, so do not include it in the create request.

## API endpoint reference

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/students` | Create a student |
| `GET` | `/students` | List students; can filter and paginate |
| `GET` | `/students/{student_id}` | Retrieve one student |
| `PATCH` | `/students/{student_id}` | Update only provided fields |
| `DELETE` | `/students/{student_id}` | Delete a student |
| `GET` | `/health` | Confirm the API is running |

### List and filter examples

- `/students?name=Aarav` — search by name.
- `/students?course=CSE` — search by course.
- `/students?born_after=2004-01-01&born_before=2006-12-31` — filter date of birth.
- `/students?limit=10&offset=0` — pagination.

For update, pass only the fields you want to change, for example:

```json
{
  "course": "AI & Data Science"
}
```

The application does not allow removing both email and phone from a record. Email addresses must be unique.

## Architecture at a glance

1. A client sends an HTTP request to a FastAPI endpoint.
2. Pydantic schemas validate incoming data.
3. The endpoint uses SQLAlchemy to read or modify the SQLite `students` table.
4. FastAPI returns a JSON response and an appropriate HTTP status code.

## Interactive dashboard and extra features

The browser-based StudentHub dashboard is served by FastAPI at `http://127.0.0.1:8000/`. It includes:

- A dashboard with total students, unique courses, email contacts, and enrollments this month.
- Search by name, email, phone, course, address, or ID; filter by course.
- Sort records by ID, name, course, date of birth, or enrollment date, in ascending or descending order.
- Client-side pagination and configurable page size.
- Export the currently filtered list to CSV; download a CSV template; import a CSV file into SQLite. CSV dates must use `YYYY-MM-DD`, and each imported record must have a name, date of birth, and email or phone. Imported records are added (not updated); duplicate emails are reported as import errors.
- Course distribution and record-completeness insights.
- Dark/light mode preference, profile detail modal, and clear success/error notifications.

The Swagger API documentation remains available at `http://127.0.0.1:8000/docs`. Use dummy student information for demos and submissions.
